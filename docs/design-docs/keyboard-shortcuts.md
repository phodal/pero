# Pero 快捷键：ChatGPT 与 Zed 对照及接入建议

建议采用 ChatGPT 的动作设置体验、Zed 的上下文分发机制，先统一 Pero 已有绑定，再补常用动作。
本记录保留初始源码与本地应用包分析。最终实现采用有限作用域和类型化覆盖，见 [ADR 0031](../adr/0031-keyboard-shortcut-contract.md)；实际运行验证见 [验收记录](../fitness/keyboard-shortcuts.md)。以下“建议”是设计输入，最终范围以 ADR 为准。

## 证据范围

- Pero：分析起点 `ada90a7c`。
- Zed：`/Users/phodal/ai/zed`，提交 `db43f05e39`。
- ChatGPT：`/Applications/ChatGPT.app`，版本 `26.1029.61003`、build `24614`。
  这个本地包的显示名为 ChatGPT，bundle identifier 为 `com.openai.codex`；不能据此代表所有 ChatGPT 客户端。
- 用户截图提供了设置页面的可见状态；另只读检查 `Contents/Resources/app.asar` 内的静态代码。
  没有读取用户聊天或修改应用设置。包中包含不同产品入口与功能开关，静态声明不等于当前入口全部可用。
- 参考分析没有启动两款应用逐一操作。随后对 Pero Native 和 Electron 做了实现验收；物理输入法未验证，详见验收记录。

## ChatGPT：动作目录驱动的设置体验

截图中一行对应一个动作，有名称、说明、一个或多个快捷键、编辑和清除入口。
例如新聊天同时显示 `⌘N` 与 `⌘⇧O`；删除聊天和新窗口等动作可以保留为未分配。
这比要求每个动作都有默认绑定更适合 Pero：用户能够发现能力，但常用键不会被低频操作占满。

本地包中的证据位置（均为 ASAR 内相对路径）：

| 路径 | 观察 |
| --- | --- |
| `.vite/build/early-bootstrap-339-a1c76730c29ac8b1.js` | 命令目录包含 `id`、标题/说明国际化键、命令菜单分组、平台默认绑定，以及部分动作的能力和入口限制 |
| `webview/assets/async/755278.0797a02097.js` | 快捷键设置包含按键录制、清除、单项恢复、全部恢复、冲突提示和重新分配操作；保存失败有错误反馈 |
| `webview/assets/async/892801.399af733ac.js` | 按名称或实际按键搜索；当前可用快捷键视图；聊天、导航、面板、项目等分组 |

命令目录显式区分 `app` 与 `os-global`，后者用于应用不在前台时的唤起等操作。
Pero 首期只需要应用内快捷键；双 Command、全局唤起、语音按住说话属于另外的产品能力。

可确认的默认声明包括：

| 动作 | macOS 默认键 |
| --- | --- |
| 新聊天 | `⌘N`、`⌘⇧O` |
| 临时聊天 | `⌘⇧N` |
| 归档 | `⌘⇧A` |
| 独立聊天 | `⌘⌥O` |
| 侧边聊天 | `⌘⌥S` |
| 复制最后代码块 | `⌘⇧;` |
| 设置 | `⌘,` |
| 查看当前快捷键 | `⌘/` |
| 侧栏开关 | Electron 声明 `⌘B`、`⌘⇧S` |
| 终端 | `Ctrl+反引号` |

绑定由 `CmdOrCtrl` 等平台表示转换。一个值得避免照搬的细节：包中的提示说明 `⌘B`
会因 Composer 光标位置而在加粗和侧栏之间变化。Pero 应优先采用明确的焦点作用域，减少位置特例。

## Zed：Action 与上下文

主要证据：

- `assets/keymaps/default-macos.json`：实际 macOS 默认绑定与上下文。
- `crates/settings/src/keymap_file.rs`：`KeymapFile` / `KeymapSection`，支持 context、连续按键、解绑和用户覆盖。
- `crates/gpui/src/keymap.rs`：按焦点上下文深度和绑定加入顺序解析；相同深度后加入的绑定优先。
- `crates/keymap_editor/src/keymap_editor.rs`：图形化编辑、按键录制、来源过滤与冲突提示。
- `crates/ui/src/components/keybinding.rs`：快捷键展示组件。

关键借鉴是“按键绑定到有名字的 Action”，而不是组件各写一份按键判断。
例如 `AgentPanel`、`AcpThread` 中 `⌘N` 对应 `agent::NewThread`；编辑器、工作区有各自的上下文。
`⌘⇧P` 打开命令面板，`⌘P` 打开文件查找，`⌘K` 后接 `⌘S` 打开快捷键配置。
`⌘B` / `⌘⌥B` / `⌘J` 对应左、右、底部 dock。

Zed 支持完整上下文表达式与多种基础键位方案，但 Pero 首期不需要把这些全部引入。
尤其不要把其冲突面板当成任意上下文重叠求解器：当前 `ConflictState` 按相同按键和归一化等价
context 分组；实际优先级还由 GPUI 分发决定。

| `crates/pero-ui/src/spotlight.rs:18` | 混合搜索会话、项目、任务和少量固定动作 | 复用搜索与列表界面，添加命令模式，不再新建另一套动作列表 |
| `crates/pero-contracts/src/workbench.rs:213` | WorkbenchPreferences | 增加用户快捷键覆盖，沿用 Host 设置保存及回执 |

具体约束与源码风险：

1. `⌘⇧A` 已打开自动化，不能无提示改成 ChatGPT 的归档。
2. `⌘1…9` 当前聚焦分栏，不是聊天或标签序号；保留这项既有语义。
3. `⌘P` 已是最近内容，`⌘⇧K` 已是全局搜索；命令面板用 `⌘⇧P` 可以明确分工。
4. `⌘K V` 已有侧边预览，不能将 `⌘K` 直接占为一个立即触发的新动作。
5. Electron 的 `⌘⇧E` 连接提示与 SettingsPanel 的聚焦导航使用同一组合，存在菜单抢占风险，需要实机确认。
6. 工作区 `Alt+Left/Right` 与 macOS 输入框按词移动相同；现有工作区绑定大量使用 `None` context。
   迁移时必须验证输入框优先级，不能假设这些绑定天然不会干扰编辑。
7. 标题栏用 `cfg!(target_os = "macos")` 选择提示；Wasm 编译目标不能反映实际宿主为 macOS。
   源码可推导其提示分支与运行时平台不一致，尚未做本轮屏幕复核。

## 建议的首批绑定

下表是 Pero 建议，非两款参考产品的完整映射。macOS 使用 `⌘`；其他平台通常用 Ctrl，
但系统保留键、终端和已有 Ctrl 绑定需要独立核对，不能机械全量替换。

| 动作 | 建议键 | 范围 / 处理 |
| --- | --- | --- |
| 新聊天 | `⌘N` | 当前工作区/App 聊天范围，沿用现有新建语义，不隐式发送 |
| 设置 | `⌘,` | 工作台与设置窗口路由 |
| 命令面板 | `⌘⇧P` | 复用 Spotlight，进入仅动作模式 |
| 查看当前快捷键 | `⌘/` | 工作台；代码编辑器内保留编辑器对该键的使用 |
| 编辑快捷键 | 先不分配 | 从设置页与命令面板进入；可后续加入 `⌘K ⌘S` |
| 显示/隐藏侧栏 | `⌘B` | 工作台；富文本编辑中保留加粗，不按光标位置切换含义 |
| 显示/隐藏聊天栏 | `⌘⌥B` | 复用现有聊天栏开闭与窄窗布局策略 |
| 打开/聚焦终端 | `Ctrl+反引号` | 复用现有终端入口，按焦点和可用性处理 |
| 最近内容 / 全局搜索 | 保留 `⌘P` / `⌘⇧K` | 不改变搜索对象 |
| 关闭 / 恢复标签 | 保留 `⌘W` / `⌘⇧T` | 只关闭视图，不删除对象或终止执行 |
| 最近使用标签切换 | 保留 `Ctrl+Tab` / `Ctrl+Shift+Tab` | 保持现有 MRU 及确认、取消规则 |
| 分栏与聚焦分栏 | 保留现有绑定 | 包括 `⌘\\`、方向组合和 `⌘1…9` |
| 归档、删除、停止运行 | 首期不新增默认键 | 已有对应动作才纳入；复用原确认、撤销或取消回执 |

临时聊天、未读跳转、复制最后代码块可以在对应行为完整时扩展；快捷键建设本身不增加这些领域能力。
Escape 首先交给输入法、候选菜单、弹层与当前局部视图；不要定义为无条件停止 Agent。

## 实现边界

先命名四个概念：`CommandId`、`ShortcutScope`、`KeySequence`、`ShortcutOverrides`。
稳定 ID 对应动作；作用域表达工作区、聊天输入、内容、终端、设置与弹层；按键序列保存规范化修饰键和键；
覆盖表示继承默认、替换绑定列表或显式禁用。没有覆盖与空列表的语义必须不同，恢复默认就是删除覆盖。

领域值和配置变换置于 `pero-contracts` 的命名模块，不引入 GPUI 或 Electron 依赖。
一次配置编辑是 `(当前配置, 编辑意图) -> (新配置, 冲突或错误)`，平台和已知作用域作为值传入。
外部配置在 Host 设置入口校验后使用类型化值；界面中的冲突预览和保存调用同一规则。
已有 GPUI Action 仍调用原来的导航、ChatPanel、终端等所有者，不新建一套业务执行器。

统一目录提供标题/说明国际化键、类别、默认绑定和允许的作用域。菜单、设置、Tooltip、命令面板
消费同一份有效配置；Electron 接收该配置的投影，不再手写默认键表。Host 只持久化用户覆盖，
不把瞬时键盘事件送入 Host 做逐键处理。编辑成功以 Host 保存回执为准，失败保留编辑内容。

GPUI 内复用已有 KeyBinding / key_context 分发。Zed checkout 与 Pero 固定依赖的 `gpui-kit = 0.9.0`
并非同一版本，实施时先确认替换、解绑与查询 API，不能照抄 Zed 当前源码或清空整个 Kit 键位表。
首期上下文采用有限、明确的作用域和关系，不引入通用 `when` DSL、用户脚本或多个 IDE 键位预设。

跨渲染边界是必要工作：GPUI 不会自动收到独立 App iframe / Native WebView 内的按键。
应用级命令在壳路由，编辑、阅读和 App 局部命令留在当前焦点 surface；只有确定被处理后才消费事件。
Electron accelerator 与 GPUI 不能各执行一次同一命令。Native WebView 也需验证同样的归属，
不能用 Electron 测试结果推定 Native 通过。无需把普通复制、粘贴统一改写成自建事件总线。

## 设置体验与交付顺序

设置导航新增“快捷键”，复用 SettingsPanel 与 pero_theme 的输入、菜单和对话框。
主列表沿用截图的动作名称、简短说明、多个键帽和未分配状态；按类别分组，补充简短作用域标签。
顶部支持名称搜索、按键录制搜索、“已修改”筛选和全部恢复；冲突编辑时直接显示占用动作与范围。
同键但互斥上下文可以共存；真正冲突允许用户取消或明确重新分配，不静默抢走另一个动作。
录制期间按键不触发业务动作，Escape 取消；完成后恢复原焦点。键帽展示从有效绑定生成。
如需新增键帽组件，应先加入共享组件库并更新实际消费者与目录示例。

建议按三个独立关切分步提交：

1. **统一目录与发现入口**：迁移已有绑定和提示，补新聊天、设置、侧栏等常用 Action，
   复用 Spotlight 增加命令模式与只读快捷键帮助。先验证焦点和跨 surface 路由。
2. **自定义与持久化**：增加纯配置模型、Host 设置覆盖、录制、冲突反馈、单项及全部恢复，
   菜单与提示随有效配置更新。扩展既有协议和生成产物，避免独立配置文件成为第二个权威。
3. **扩展真实消费者**：独立 chat-only 产品和更多 App 的局部动作按实际需求接入；
   系统全局唤起、多套预设、任意用户上下文表达式保持在首期范围外。

每阶段可按 contracts、壳接线、设置 UI 再拆 baby-step commits，避免把完整迁移挤进一个提交。
删除旧常量前搜索所有引用，保留上表现有行为与已修复编辑路径。

验证以配置语义表为主：默认/覆盖/禁用/恢复、多绑定、平台差异、作用域冲突与序列前缀。
少量实际壳验收覆盖：快捷键与点击效果一致；菜单与 GPUI 只执行一次；iframe/Native WebView
内仍可打开应用级入口；输入法 Enter/Escape 不误发、不误停；终端输入不被劫持；保存后重启保持，
恢复默认后菜单和 Tooltip 同步。设置页还需按 DESIGN-REVIEW 检查两主题、窄窗、键盘与焦点返回。
Windows/Linux 和物理输入法分别记录验收，当前分析不声称通过这些检查。
