# Paper Agent 稿件写作与构建预览

论文生命周期能力融入 `apps/paper-agent`。用户从现有 Paper App 阅读文献、整理
证据，继而规划、写作、编译预览、审阅和交付自己的稿件。App 身份、研究项目关联、
共享 Host Chat 和数据所有权保持统一。

当前新增四个阶段 Skill 和 builtin payload 中的交付文件。本文中的稿件存储、
构建工具与编辑预览界面是待实现设计；现有来源阅读和报告能力不能视为这些功能的验收。

## 所有权

| 所有者 | 职责 |
| --- | --- |
| Paper Agent Python 领域 | 稿件版本、主张与证据关系、构建产物引用、审阅意见 |
| Paper Agent Skills | 规划、写作、构建、审阅的任务指引与证据边界 |
| Paper Agent 后端适配 | 已声明的领域读写、确定性编译诊断、产物交付与导出 |
| Paper Agent Web UI | 文献/证据到稿件的关联、正文/TeX 编辑、PDF 预览与问题定位 |
| Host/ACP | 模型与会话、授权、进程生命周期、取消和历史 |
| 研究 Project | 引用 Paper 拥有的论文、研究与稿件对象，保留研究目标 |

沿用 [ADR 0027](../adr/0027-app-agent-plugins.md) 的机制时，Agent Plugin 只是
App 内部的技能/工具装配方式。初版阶段 Skill 沿用 App 已有 `skills/` 布局，
无需独立产品、插件市场或额外的安装流程。工具权限和能力来自真实 App 声明，
Skill 文字不能增加权限。

## 生命周期入口

| 目标 | 能力 | 交付 |
| --- | --- | --- |
| 收集与读证据 | 既有 resource-import、ResearchStudy 与 source reports | 固定版本来源与原文观察 |
| 组织论证 | `paper-plan` | 贡献句、主张证据表、提纲、缺口 |
| 写作与修改 | `paper-write` | 正文/TeX、引用、图表关联与稿件版本 |
| 编译和查看稿件 | `paper-build` 与后续 App 构建适配 | 实际 PDF、构建诊断、精确版本预览 |
| 评审并修订 | `paper-review` → write/build | 定位意见、证据和修订记录 |
| 可编辑交付 | build/export 操作 | TeX、BibTeX、引用资产、PDF 与检查说明 |

用户按当前任务进入对应阶段。局部润色不要求重做选题和检索，已有 TeX 可直接
构建；实验缺口交给已授权的复现/实验工作流。阶段不各自建立 Agent、Composer
或执行队列，也不引入一个强制线性流转的论文总状态机。

## 稿件和研究来源

在同一 App 内区分外部来源 `PaperSnapshot` 与作者稿件 `ManuscriptRevision`。
现有 `ResearchReport` 是对冻结输入的研究回答，继续保存原有证据语义；阅读模式
的 `experiments=[]` 约束保持适用。作者稿件使用新领域对象，引用已保存的原文
观察、研究报告和实际实验产物。

建议从实际需要的概念开始：

- `ManuscriptRevision`：正文与资产清单、父版本和既有来源引用。
- `EvidenceRef`：指向真实原文观察或实验结果，携带准确版本与位置。
- `ManuscriptClaim`：稿件文字、位置、支持与冲突关系及判断范围。
- `BuildAttempt`：固定输入、实际执行引用、诊断与产物，不复制执行队列状态。
- `ReviewFinding`：稿件/构建版本、文字/页码位置、问题、依据和修正建议。

具体工作记录约定见
[证据契约](../../apps/paper-agent/skills/paper-write/references/evidence-contract.md)。
这些概念在 Python 领域实现为不可变值，外部输入在边界解析一次；纯函数根据值
决定新状态与 effects，存储和执行适配承担 I/O。

来源存在、元数据准确、原文支持断言、数值来自实际结果是不同检查。哈希、来源 ID、
精确引用和编译退出码分别证明自己的范围，不共同隐含科学结论已接受。必要的不确定性、
失败样本、分母、单位和条件随主张保留。

## TeX 构建和 PDF 预览

作者选择模板和已授权工作区后，写作阶段生成/修改 `main.tex`、章节、BibTeX
及图表引用。模板、字体和引擎要求可追溯；图表使用原始资产或从已识别数据生成。
现有来源获取路由保持只读语义，下载 TeX 不等于获准编译。

首版只实现实际选定的一种本地构建路径，按模板使用准备好的 TeX 环境和记录命令。
构建输出与作者源文件分开，记录输入清单、环境、命令、真实进程结果、日志和 PDF
哈希。环境缺失、源码语法、资源缺失、引用及布局警告分别定位。执行与取消沿用
现有授权/执行所有者；出现第二种实际构建实现时再考虑接口。

预览通过本 App 的稿件产物路由交付精确 PDF。现有 EmbedPDF/PDFium 渲染组件
可以复用，但当前 Paper/PDF-ID 路由和 reader 数据模型需要稿件适配，不能把作者
稿件伪装成一篇外部文献来复用路由。

正文/TeX 和 PDF 使用 App SDK `Split`/`SplitPane`，诊断和意见按需展开。
源码变化时旧预览显示待更新；新构建失败时保留上次成功 PDF，显式关联其版本并
展示当前错误。审阅页码绑定具体构建，不能随新 PDF 静默移动。先支持错误行导航
和准确版本预览，再用真实 SyncTeX 文件接双向定位。

空稿件、加载、缺少环境、编译中、成功、构建失败和历史预览均有明确状态与恢复
动作。共享 Chat 中的稿件/选区引用仍通过既有 SDK 冻结到草稿，由 Host 会话执行。
PDF 已生成、预览已打开、实际页面已被模型/人检查分别记录。

## 接线与实施顺序

1. 作者稿件：新建/打开及保存版本，关联既有研究证据，声明实际领域路由。
2. 本地闭环：TeX 保存、一次真实构建、精确 PDF 预览、错误定位与恢复。
3. 主张检查与评审：重要数值/分母/单位检查、证据支持审阅、版本化意见和修订。
4. 按需扩展：SyncTeX、批注、Zotero、Overleaf diff/显式同步与交付包。

技能文件和所需参考资料已列入 builtin payload 白名单；这只证明可随 App 交付。
Desktop 自动发现、资料可读、会话挂载和新领域工具准入需分别接线和验证。
headless 用户沿用显式 `--skills-root`；catalog 只读取 SKILL.md，参考文件需要
独立授权的文件读取能力。不得把未声明的提案工具当成已存在接口。

## 验收

技能格式与离线 staging 检查验证安装资源完整。领域测试检查版本、证据、构建
输入和产物关联；少量 shell 测试证明实际编译/失败/取消/恢复的接线。

运行 App 后，使用已有研究材料完成写作、编译、预览、错误修复与导出；检查实际
截图、PDF 页、窄窗/暗色、键盘焦点和诊断跳转。验证改稿后的旧预览提示与失败后
保留历史 PDF。fixture、真实模型、实际工具链和安装包验收分别记录。没有 TeX
引擎时应清楚报告环境缺失，不能以生成源文件代替编译成功。
