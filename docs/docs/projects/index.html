用研究项目组织材料与对话

围绕一个研究问题保存目标和 App 材料引用，把同一项目的对话、审批与产物留在可回看的记录里。

本页目录

  • 创建可继续的研究项目
  • 关联材料并回到来源
  • 让 Project Agent 处理一个有界任务

创建可继续的研究项目

  1. 打开侧栏项目，点击新建研究项目，输入项目名称和研究目标，例如“复核 Fisher 表 III 的组内平方和并逐项记录输入”。
  2. 若还要使用项目文件、工作区任务或委派文件检查，填入本地目录的完整路径。只整理 App 里的研究材料时可以留空。
  3. 点击保存项目。重新打开该项目，应能看到同一个目标和材料区。之后用编辑目标更新研究问题。

关联材料并回到来源

  1. 先在 Paper 保存一篇论文或研究记录，或在 Control Lab、Lab 保存一项实验。
  2. 在项目右侧的概览找到资料与实验 → 关联已有记录，选择已启用的来源 App 与具体记录。也可从项目视图进入资料页。
  3. 点击关联记录确认能回到来源 App。如出现原记录已变化，先核对当前原记录再点更新关联版本。若记录不可用，项目仍保留引用，可以恢复来源或解除关联。

项目保存的是关联关系和观察到的版本。修改或解除关联只改变项目记录。精确交接请同时保留来源 App 的版本号、内容摘要或试验归档。

让 Project Agent 处理一个有界任务

当前源码包含 Project Agent。2026-11-12 的开发预览包发布时尚无该入口。准备可用的 Agent 和工具及一个本地目录，打开已保存的研究项目。点开始项目对话，在中央的主 Agent 对话中提交一个可检查的小任务。

请委派一次只读检查，列出本项目目录用于组内平方和复核的输入文件，列出各自路径和 SHA-256。保留原文件，把未核对的项目单列。

  1. 若主 Agent 创建子会话，在侧栏打开它，检查任务范围和审批卡。按实际命令决定是否允许。
  2. 展开子会话的工具记录，查看实际命令、退出码与输出，检查是否只读取了预期的材料。Git 项目的委派工作保存在独立工作树中。需要合并时，先检查实际改动。
  3. 从项目 Agent 的控件选择汇总证据与结果，在主 Agent 对话中阅读依据、缺口和原始会话。在有用回复的消息操作中保存产物，再从项目的产物视图回查。

刷新或重启后可从项目回到原会话、历史与已保存产物。尚未完成的指令需要人工判断后继续。读取失败时先刷新，保留原会话。开发版已用脚本化模型和实际本地执行验证上述流转，真实模型结果与科学验收请单独核对。
