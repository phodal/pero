先检查方法需要的软件

打开侧栏的执行环境，如果入口未出现，在应用中启用它。也可以从 Paper 的复现面板或 Control Lab 的引擎可用性入口查看对应方法。

  1. 打开软件检查，选择要用的方法，如 Control Lab 的 python-control。手动启动检查，查看方法所需软件、当前观察到的版本和缺失项。
  2. 记录方法以及检查结果。可导出带版本的观察记录。打开列表只读取已保存的信息，软件检查只观察配置所指的软件。

版本匹配之后，还需要准备或选择环境，并在所属 App 单独运行实验。软件检查结果没有实验产物或结论。

安装并切换 App 服务环境

  1. 打开执行环境 → App 服务环境 → 创建环境，填写名称，选择方法，例如 Control Lab 的控制系统仿真。核对将安装的运行时和依赖，再点创建并准备。
  2. 等待准备完成。安装失败时展开安装日志，根据错误检查依赖获取或本机软件，再用重试继续。首次准备可能联网安装 Python 和方法依赖。
  3. 保存目标 App 中的工作，再点使用此环境 → 绑定并重启。此操作会重启 App 后端并停止该 App 正在进行的计算。看到当前使用后，到目标 App 中重新检查软件。Control 和 Circuit 共用 Control Lab 的服务环境。

已绑定环境请通过创建新环境来变更依赖。只需阅读 Paper 时，可以直接完成Paper 首次环境准备。

为实验选择锁定计算环境

在支持的 macOS arm64 或 Linux x64 构建中，执行环境 → 计算环境可为 Control Lab 或 PC-Gym 创建独立计算环境。选择方法，创建环境，再点击准备环境。准备成功后，可查看 uv.lock 对应的锁文件摘要及依赖内容摘要。

选择用于此方法计算后，新实验使用选定环境，App 服务继续运行。已有实验固定原环境。需要继续旧实验时选回原环境，也可在当前环境开始新实验。要重建已准备好的环境，用按同一锁重建生成独立副本。

准备记录包含安装与导入检查。正式计算仍从 Control Lab 或 Paper 的实验入口发起，按该方法的审批、运行和验收步骤进行。已经准备环境的证据和平台范围见计算环境说明及验证记录。

为 SSH 或 Slurm 配置连接

版本要求。以下远程提交、观察和收集流程对应当前源码。2026-11-12 预览包中的 Compute 只能保存集群配置、查看已有回执或导入报告。需要下列功能时，请使用包含远程执行的构建。从源码启动。

  1. 向站点管理员确认授权的 SSH 别名、主机身份及可写工作目录。在系统 OpenSSH 中配置免交互访问和已验证的 known_hosts 记录。应用使用系统 SSH 配置和 Agent，表单仅保存非密钥字段。
  2. 在科学计算的集群设置中点添加集群配置，填写名称、登录主机或 SSH 别名和远端绝对工作目录。选择 SSH 工作站或 Slurm / SSH。准备 Slurm 作业时分区为必填，账号按站点要求填写。工作目录需供登录节点和计算节点共同访问。
  3. 保存后打开远程执行，选择该连接并点击探测连接。看到已验证连接时，核对主机、观察到的平台与 Python，以及 Slurm 的集群身份。探测反映提交端所见的软件，实际分配节点信息随作业回执查看。

登录侧需要可非交互访问的 Python 3。Slurm 还需站点的调度命令、节点上的 Python 3，以及账号对固定资源请求的授权。站点检查项。

运行一次可核对的求积示例

  1. 在远程执行设每次采样数为 1000，重复次数为 1，点准备并固定输入。内置 CPU 方法计算 0 至 1 上的 4 / (1 + x²) 积分。
  2. 检查已准备，等待批准状态，以及固定输入与目标中的尝试编号、远程目录和 SHA-256。使用 Slurm 时检查账号、分区、1 CPU、256 MiB、600 秒约束。准备会创建远程尝试目录。确认目标与参数后点批准并提交，此时才发起计算。
  3. 在已保存执行选中这次尝试，点读取原执行状态查看日志、已记录的退出码和 Slurm 作业标识。排队表示提交已入队，分配状态需随后观察。
  4. 执行结束后点收集并保存证据，再下载原始产物。成功时 result.json 的 estimate 约为 3.1415927369，与 π 的绝对误差约 8.33e-8，阈值为 1e-6，checkPassed 为 true。scientificAcceptance 保持 unreviewed。

复制 compute:<attempt>:<sha256> 引用到研究记录，可定位这次在本机固定下来的原始字节。远端文件后续修改不会改变已收集内容。数值与回执只验证这次固定方法的执行。

恢复原执行与重收集证据

探测失败或准备未完成
检查主机别名、系统 SSH 授权、工作目录权限或 Slurm 账号/分区。修正配置后再探测，准备未完成的尝试需重新准备。
已提交但未收到回执，或状态为「需要核对」
刷新已保存执行，再读取原执行。保留尝试编号与远程目录，请站点人员按原作业身份及提交时间核对后再决定下一步，避免重复提交。
已请求取消
继续读取原执行，等执行方确认停止。关闭 App 或退出 Pero 后，已提交的远程计算会继续，重新打开可继续观察原尝试。
收集不完整
先保存已有下载和固定引用。解决远程文件缺失或访问问题再点重试收集缺失证据。每份收集文件上限为 1 MiB，过大文件仍保存在远程目录。

开发构建的验证覆盖真实回环 SSH 与 Slurm 测试替身。这个流程提交内置 CPU 方法。真实 Slurm 站点仍待验收。远程执行验证记录。
