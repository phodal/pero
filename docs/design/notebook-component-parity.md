## Real external boundaries versus unfinished implementation

**Not external blockers:** remaining review configuration, field/autofill workflows, procedure parameter relationships, research/print affordances, provenance/format extensions and App Canvas platform contract. Already implemented draft/history/code/image/sample/formula features still need exact-head acceptance, not wholesale reimplementation. “The reference is stubbed” is not a reason to omit them.

**Owner/configuration dependencies:** live model execution requires an available configured Host model/session; current Canvas navigation requires an installed App/panel; embedding/actions additionally require completing the in-progress Host contract; cross-App lookup/inventory/instrument operations require the actual owning App contract and permissions. Report the exact missing route, installation, model or authorization. Wiring to an owner that already exists is implementation work, not an external blocker.

**External assurance:** multi-user identity, authenticated reviewer decisions, compliant e-signatures, notifications/delivery, remote registry commits, inventory deductions and instrument runs require their actual identity/service/hardware owners. Local persisted records can be real local records but cannot attest to those external events. Reference tenant credentials are only relevant to an explicitly requested Benchling integration, not to implementing Pero equivalents.

**Reference source/assets:** unknown reuse licensing blocks copying those materials, not original capability implementation. A searchable local capability catalog can document Pero methods and supported contracts without redistributing the recovered private index.

## Completion criterion

Create a published template fragment, insert it twice with disjoint IDs, save/query/freeze materials, register a real local material, distinguish mixture target from recorded actuals, refresh/freeze lookup, execute a declared Canvas action, review real model suggestions against a fixed input revision, add anchored comment/task/review, edit and show review staleness, compare/restore history, then reload and export/import. Verify retained identities, provenance and receipts, plus failures and cancellation. Until this and the outstanding family workflows are verified, the accurate claim is **substantial local coverage with explicit remaining gaps**, not “all components implemented.”
