Inspect, chart, and share data

Inspect the full input at a specific file version, check fields and issues, chart the results, and save a view that opens the original records.

On this page

  • Follow a six-record example
  • Check field types and inspection scope
  • Pin a version, save a view, and export
  • Recover from file and inspection issues

Follow a six-record example

Open Data in the desktop workbench and download first-dataset.json. The three fields in this synthetic sample are condition, replicate, and signal. Inspection and charting work offline once you have the file.

  1. Choose Add data, select the downloaded JSON, keep the type set to Dataset, and choose Import. Open the entry and select Explore data. Expect 6 records and 3 fields.
  2. In Table, set Filter field to condition and Condition to Equals. Enter treated and choose Apply. Expect original rows 4–6 with signal values 1.3, 1.4, and 1.5. Open Source on one row to check its location in the original file.
  3. Name the view Treated only and choose Save view. Under Checks, the full-input scope still contains 6 records. Missing fields, explicit nulls, empty strings, and duplicates each have count 0.
  4. Return to Table and clear the filter and row selection. Under Chart, choose bar → Current aggregation, set Group by to condition and Measure to signal, then set Aggregate to Sum. Open Chart data and expect 3 for control and 4.2 for treated. With Count, each group has 3 records.

Charts use the matching records or an explicit selection. If only the treatment group appears, check the filter and selected rows in Table. These totals help you check the tutorial input and aggregation.

Check field types and inspection scope

Data inspects UTF-8 CSV, TSV, JSON, and JSONL/NDJSON. Imports are limited to 10 MiB. A single inspection supports up to 100,000 records and 256 fields. The table pages results from the full inspection. If parsing fails, review the reported cause.

  • CSV and TSV values start as text to preserve identifiers such as 001. To filter or aggregate numerically, open Fields and choose Preview number → Apply type for that column. Check the examples that fail conversion. Values with currency symbols, thousands separators, or outer spaces need review. Failed values retain their original text.
  • JSON preserves the difference between a missing field, null, and an empty string. Missing and conversion counts are cell counts. Duplicate counts are row counts. Opening issue rows pauses the table filter. Choose Return to analysis to restore your analysis.
  • Units are view labels. Changing a label from cm to mm leaves the values intact. For a conversion, retain the rule and the new dataset version.

Pin a version, save a view, and export

  1. To update a dataset, choose More → Add version on the existing entry. Older versions retain their original bytes and identifiers. Add data from the library creates a separate entry, even for the same filename.
  2. Under Overview → Saved views, open Treated only to recover its input version and the three matching rows. Check the SHA-256 under Files or Versions. Reopening the view rechecks the original bytes.
  3. Export reference downloads a JSON reference containing the pinned asset, parser, view, and check report. Include the original file or an accessible source with that reference. Use Export records for the current data subset and Export chart JSON for the chart.

Reports and exports keep source locations and analysis settings. Data’s Project reference groups datasets. The underlying files or services govern access. See research projects for a separate materials index.

Recover from file and inspection issues

  • Missing or Changed. The catalog record remains. Restore the original bytes matching the admitted digest, or add a new version and save a new view.
  • Unexpected numeric filter results. Check the field interpretation, conversion failures, and filter scope. Exact numbers and original text are recorded separately.
  • A model file has no table. Data records its source and versions. Loading weights and running inference require a suitable method and execution environment.
  • Archiving did not free space. Archiving moves an entry to Archived and keeps its versions and views available to restore.

See the Data inspection rules and the workbench verification record.
