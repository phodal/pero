Inspect, chart, and share data

Inspect the full input at a specific file version, check fields and issues, chart the results, and save a view that opens the original records.

On this page

  • Follow a six-record example
  • Check field types and inspection scope
  • Pin a version, save a view, and export
  • Recover from file and inspection issues

Follow a six-record example

This walkthrough was verified with the macOS Apple Silicon Electron package v0.1.0-dev.20261112. Open Data in the workbench sidebar and download first-dataset.json. The synthetic sample contains condition, replicate, and signal. If the App displays Environment not ready, choose Prepare environment and wait for Add data. First-time preparation can need network access. The remaining steps run locally.

  1. Choose Add data, select the downloaded JSON, keep the type set to Dataset, and choose Import. This release opens Table after import. Expect Bytes matched, 6 records and 3 fields.
  2. In Table, change No filter to condition and choose Equals. Enter treated and choose Apply. Expect original rows 4–6 with signal values 1.3, 1.4, and 1.5. Source beside row 4 opens a read-only document tab with that record selected. Select Data again to return to the filter.
  3. Enter Treated only in View name and choose Save view. Look for “View and checks saved against this exact version.” Under Checks, the full-input scope still contains 6 records, and missing fields, explicit nulls, empty strings, and duplicates each have count 0.

Return to Table and choose Clear filter before plotting both groups. In Chart, choose bar and Current aggregation, set Group by to condition and Measure to signal, then set Aggregate to Sum. Expand Chart data (2). The package displays 3.0 for control and 4.2 for treated. With Count, both values are 3. The bar order can differ from the input order.

Check field types and inspection scope

Data inspects UTF-8 CSV, TSV, JSON, and JSONL/NDJSON. Imports are limited to 10 MiB. A single inspection supports up to 100,000 records and 256 fields. The table pages results from the full inspection. If parsing fails, review the reported cause.

  • CSV and TSV values start as text to preserve identifiers such as 001. To filter or aggregate numerically, open Fields and choose Preview number → Apply type for that column. Check the examples that fail conversion. Values with currency symbols, thousands separators, or outer spaces need review. Failed values retain their original text.
  • JSON preserves the difference between a missing field, null, and an empty string. Missing and conversion counts are cell counts. Duplicate counts are row counts. Opening issue rows pauses the table filter. Choose Return to analysis to restore your analysis.
  • Units are view labels. Changing a label from cm to mm leaves the values intact. For a conversion, retain the rule and the new dataset version.

Pin a version, save a view, and export

  1. To try versioning, make a copy named first-dataset-v2.json and append {"condition":"treated","replicate":4,"signal":1.6} as the seventh array item. Choose Add version beside the current version selector and import the copy. Table shows 7 records for v2. Add data from the library creates a separate entry, even for the same filename.
  2. Under Overview → Saved views, open Treated only. It restores v1 — first-dataset.json with the three original matching rows. The same view reopened after restarting the workbench. Reopening the view rechecks the original bytes.
  3. Export reference next to the saved view downloads JSON containing its v1 SHA-256, the condition = treated filter and the full-input six-record check report. Include the original file or an accessible source with the reference. Use Export records for the current data subset and Export chart JSON for the chart.

Reports and exports keep source locations and analysis settings. Data’s Project reference groups datasets. The underlying files or services govern access. See research projects for a separate materials index.

Recover from file and inspection issues

  • The chart shows only treated. The chart uses matching or explicitly selected records. With the sample filter still on, the package showed a single group. Return to Table, choose Clear filter and check that 6 rows are visible with none selected.
  • Missing or Changed. The catalog record remains. Restore the original bytes matching the admitted digest, or add a new version and save a new view.
  • Unexpected numeric filter results. Check the field interpretation, conversion failures, and filter scope. Exact numbers and original text are recorded separately.
  • A model file has no table. Data records its source and versions. Loading weights and running inference require a suitable method and execution environment.
  • Archiving did not free space. Archiving moves an entry to Archived and keeps its versions and views available to restore.

See the Data inspection rules and the workbench verification record.
