Environments and remote compute

Check local software, prepare an environment for an App or an experiment, and explicitly approve a built-in computation on an SSH workstation or Slurm.

On this page

  • Check a method’s software requirements
  • Prepare and bind an App service environment
  • Select a locked computation profile
  • Set up an SSH or Slurm connection
  • Run a quadrature example with a known result
  • Recover the original run and collect missing evidence

Check a method’s software requirements

Open Environments from the sidebar. If it does not appear, enable it in Apps. The Paper reproduction panel and Control Lab engine availability also open checks scoped to that method.

  1. Open Software checks and select a method, such as python-control for Control Lab. Run the check and review required software, observed versions, and missing packages.
  2. Record the method and check outcome. You can export a versioned observation. Opening the list reads saved entries. Starting a check inspects the software referred to by the current configuration.

Once the software matches, prepare or select the environment and start the experiment in its own App. The software observation contains compatibility information. Experiment outputs and conclusions come from the subsequent run and review.

Prepare and bind an App service environment

  1. Open Environments → App environments → Create environment. Enter a name and choose a method, such as control system simulation for Control Lab. Review the runtime and packages, then choose Create and prepare.
  2. Wait for Prepared. If preparation fails, open Installation log, check the dependency source or local software reported in the error, and choose Retry. First-time preparation can download Python and the method's dependencies.
  3. Save work in the target App, then select Use this environment → Bind and restart. This restarts the App backend and stops its calculations. When Currently in use appears, verify the software in the target App. Control and Circuit share the Control Lab service environment.

Create a new environment when changing the dependencies of a bound environment. To read PDFs, use the simpler first-time Paper environment setup.

Select a locked computation profile

In supported macOS arm64 and Linux x64 builds, Environments → Compute creates a separate environment for Control Lab or PC-Gym. Choose a method, create a profile, and select Prepare environment. Once prepared, inspect the uv.lock and package content digests.

Choose Use for this method to select the environment for new experiments. The App service continues running. Existing experiments keep their original environment. To continue an existing experiment, select its original environment. To rebuild a prepared profile in a separate location, use Rebuild from same lock.

Preparation records installation and import checks. Start the computation from Control Lab or Paper and use the method's own approval and review steps. See the compute profile documentation and platform verification.

Set up an SSH or Slurm connection

Version requirement. The submission, observation, and collection steps below describe the current source. The November 12, 2026 preview of Compute saves connection drafts, displays available receipts, and imports reports. Use a build containing remote execution to follow this walkthrough. See launching from source.

  1. Confirm your authorized SSH alias, host identity, and writable work directory with the site administrator. Set up noninteractive access and a verified known_hosts entry in OpenSSH. The App uses system SSH configuration and its agent. The form stores non-secret connection details.
  2. In the Compute cluster settings, choose Add cluster draft. Enter a name, login host or SSH alias, and absolute remote working directory. Select SSH workstation or Slurm over SSH. For Slurm, specify a partition, add the account if your site requires it, and use a work directory shared by the login and compute nodes.
  3. Save the draft, open Remote execution, select the connection, and choose Probe connection. When Connection verified appears, review the host, platform, Python version, and Slurm cluster identity where available. The probe observes the submission host. Job receipts report allocated nodes when observed.

The login host needs Python 3 on the noninteractive path. Slurm also needs the scheduler commands, Python 3 on the allocated nodes, and site authorization for the fixed resource request. See the site requirements.

Run a quadrature example with a known result

  1. In Remote execution, set Samples per repetition to 1000 and Repetitions to 1. Select Prepare fixed inputs. The bundled CPU method integrates 4 / (1 + x²) over the interval from 0 to 1.
  2. Look for Prepared, awaiting approval. Under Frozen inputs and destination, review the attempt ID, remote directory, and SHA-256. For Slurm, check the account, partition, 1 CPU, 256 MiB, and 600-second limit. Preparation stages a remote attempt directory. Select Approve and submit when the destination and parameters are correct.
  3. Open the attempt under Saved executions. Use Observe original execution to see logs, any recorded exit code, and the Slurm job identity. A queued job is awaiting allocation. Observe again to check whether it has started or stopped.
  4. After the execution ends, select Collect and save evidence, then Download original. On success, the estimate in result.json is about 3.1415927369. The absolute error against π is about 8.33e-8, with a tolerance of 1e-6 and checkPassed set to true. The scientificAcceptance field remains unreviewed.

Copy the compute:<attempt>:<sha256> reference into your research record to identify the exact bytes collected locally. Later remote changes leave those collected bytes intact. The result and receipt establish execution of this fixed method.

Recover the original run and collect missing evidence

Connection probe or preparation failed
Check the SSH alias and authorization, work directory access, and any Slurm account or partition. Probe after correcting the configuration, then prepare a new attempt if staging was incomplete.
Submission reply was lost or the run needs reconciliation
Refresh saved executions and observe the original attempt. Preserve its identity and remote directory. Ask the site operator to reconcile the original job identity and submit time before starting another run.
Cancellation requested
Observe the original attempt until the owner confirms stop. A submitted remote run can keep running after closing Pero. Reopen Compute and inspect that same attempt.
Collection is incomplete
Keep the files and fixed references you already have. Resolve missing files or access issues, then choose Retry collecting missing evidence. Collection is limited to 1 MiB per file. Larger files remain in the remote directory.

The development verification covers authenticated loopback SSH and a Slurm fixture. This workflow submits the built-in CPU method. Live-site Slurm acceptance remains open. See remote execution verification.
