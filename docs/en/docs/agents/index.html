Configure Agents and tools

Connect a built-in or external Agent, confirm a plain-text reply, then add a workspace, context, and tool access for your task.

On this page

  • Verify your first model reply

Configure the built-in Pero Agent

  1. Open Settings → Built-in Agent. Enter the API URL, Model, and API Key provided by your service. The built-in defaults are https://api.deepseek.com and deepseek-chat. Use HTTPS for the URL, with HTTP available on loopback. Enter the model ID in the model field.
  2. Select Save and look for Saved. Desktop encrypts the key through the system credential store. Leave the key field empty to keep the saved key when editing the URL or model. To clear it, select Remove saved key and confirm.
  3. Open New chat and select Pero (DeepSeek) near the composer. The new session uses your saved configuration.

Saved settings take precedence over development DEEPSEEK_* variables and .env. Existing sessions keep the configuration they started with. See launching from source and the Desktop configuration reference.

Connect an external Agent

Pero connects to external Agents using local ACP adapters. Open Settings → Models & Agents to see which adapters are available. Each Agent has its own sign-in and model settings.

Codex and Claude
The Electron development preview bundles both ACP adapters. When running from source, npm ci at the repository root installs the project's adapters. Follow the session's sign-in instructions, then select a model offered by the Agent.
GitHub Copilot, Grok, Qoder, and OpenCode
Install the ACP-capable local CLI and complete its provider configuration or sign-in. The registered executables are copilot, xAI's grok-build or the grok in its own installation directory, qodercli, and opencode. Restart Pero after installation and check the selector again.

If the session asks you to sign in from a terminal, finish the Agent's terminal sign-in, then return and select I have signed in · Continue. Follow the Agent's buttons for other sign-in methods. Review the original prompt and send it again yourself after authentication.

Verify your first model reply

  1. Open New chat. Use the folder button by the composer to choose an empty practice directory, then select a configured Agent. The workspace is the local execution target for that session. Once you have started the conversation, open a new chat to change the Agent or workspace.
  2. Send a short prompt that needs no tools or attachments. If asked to sign in, complete the steps above and submit the prompt again.

Reply with exactly PERO_SETUP_OK. Please do not call tools or read or change files.

The expected reply confirms a round trip to the model. Installed confirms adapter discovery, and ACP can connect before model sign-in. After getting a reply, try the paper passage walkthrough to check the Agent against your research task.

Review workspace and permission scope

Start in a dedicated folder. Use the context menu in the composer to choose files to send, then review the draft and references before submitting. The folder gives the local Agent a working location. Your message and data read through tools can reach the selected model provider.

  • Permission choices follow the Agent's capabilities. With the built-in Agent's View only mode, the Agent can read the workspace. File changes and commands are rejected. Edit in workspace asks before writing and rejects commands.
  • Full access asks before file changes and commands. Auto-review allows these actions without a prompt. The built-in Agent's commands in these modes run without OS sandboxing. Available modes can differ by platform and external Agent.
  • When Permission required appears, expand the related tool and review the action and destination. Approve once if the Agent offers that choice, or decline and revise the request. Select Stop to request an end to the active turn. Check the original service for effects that already happened.

Add MCP tools with Connectors

  1. Open Connectors in Workbench or from the Apps catalog. Choose a trusted service, save its configuration, and complete its sign-in. If consent opens in a browser, review the account and scope. Enter credentials only in the connector's dedicated fields and keep them out of URLs, arguments, examples, and chat.
  2. Select Verify connection. A verified connection has discovered tools and released the probe connection. Review the Tools list, select the tools needed for this task, and save. Use the actual connection result to determine which tools are available to this account.
  3. Start a new conversation to use the connection. Host fixes the connector configuration and selected tools for that session. Changes to credentials or permissions invalidate the older connector snapshot. Open a new chat after saving, then verify with a read-only operation documented by the service.

Direct per-Agent MCP configuration is saved separately and depends on adapter support. For features such as full-text paper search, the Agent needs the applicable MCP transport. The managed Connectors runtime is available on macOS and Linux and reports an unsupported platform on Windows. See the Connectors design and platform verification.

Troubleshoot sign-in, models, and tools

The Agent is missing or disabled in the selector
Check that Desktop can find the CLI or adapter, restart Pero, and open the selector again.
The built-in Agent needs an API key, or saving fails
Check that the URL, model ID, and key belong to the same service. If the system credential store is unavailable, unlock it, reopen Desktop, save, and try a new chat.
The Agent connects and the model rejects the request
Resolve the authentication error using that Agent's sign-in flow. If the Agent offers a model selector, choose a model available to the account. Confirm the plain-text reply above before adding tools.
A tool is unavailable or denied
Check the connection test, the tool selection, the session's permission mode, and the Agent's transport support. Start a fresh conversation after a configuration change. If the outcome of an external write is unclear, inspect the original service's record before deciding whether to repeat it.

Record the package version, Agent name, shareable error text, and steps to reproduce. See verification scope and issue reporting.
