Organize materials and conversations by project

Keep a research goal and relevant App records together, with project conversations, approvals, and artifacts you can return to later.

On this page

  • Create a research project you can resume
  • Link materials and reopen the source
  • Give Project Agent a bounded task

Create a research project you can resume

  1. Open Projects in the sidebar. Choose New research project and enter a name and goal, such as “Recheck the Fisher Table III within-species sum of squares and document each input.”
  2. Enter an absolute local directory path if you plan to use project files, workspace tasks, or delegated file inspection. Leave it empty when organizing App materials alone.
  3. Choose Save project. Reopen the project and confirm the goal and materials area are available. Use Edit goal to update the research question later.

Link materials and reopen the source

  1. Save a paper or research record in Paper, or save an experiment in Control Lab or Lab.
  2. In the project’s right-hand Overview, choose Materials & experiments → Link existing records. Select the enabled source App and the record. You can also enter Materials from Project views.
  3. Open the link and confirm it leads to the source App. If the original record changed, inspect that version before choosing Update linked revision. If it is unavailable, the project retains the reference so you can restore the source or choose Unlink.

The project stores the association and observed revision. Updating or unlinking affects only the project record. For a handoff, retain the source App’s version, content digest, or trial archive as well.

Give Project Agent a bounded task

Project Agent is available in the current source build. The November 12, 2026 preview predates it. Prepare a working Agent and tools and a local directory, then open a saved research project. Choose Start project conversation and submit a small, checkable task in the central Main Agent conversation.

Delegate a read-only check of the input files for the within-species sum of squares in this project directory. List each path and SHA-256, preserve the original files, and list anything you could not check.

  1. If the Main Agent creates a child conversation, open it from the sidebar and review its task and approval card. Decide whether to allow the specific command.
  2. Expand the tool entry in the child conversation. Inspect the command, exit code, and output, and check that it read only the intended materials. Delegated work in a Git project has its own worktree. Review any changes before integrating them.
  3. Choose Summarize with evidence from the Project Agent controls. Read the evidence, gaps, and original conversations from the Main Agent conversation. Use the message action to save a useful reply as an artifact, then reopen it from the project’s Artifacts view.

After refresh or restart, use the project to reopen the original conversations, history, and saved artifacts. Decide how to continue unfinished instructions after checking their state. If conversation loading fails, refresh first and keep the original session. Development workbench verification used a scripted model with actual local execution. Review real-model output and scientific acceptance separately.

See the Project Agent interaction and restart verification.
