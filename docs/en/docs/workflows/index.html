Research workflows

Inspect a dataset version, recheck a published result, or organize materials in a research project. Check the linked verification records for versions and coverage.

Inspect a dataset version

  1. Save these six synthetic records as first-dataset.json. In Data, choose Add data, select the file, and confirm the import.
  2. Open the dataset and choose Explore data. Confirm the six records and three fields, then check the selected version and SHA-256 under provenance.
  3. Save a view to retain filters or chart settings. To append a revision, choose Add version on the existing entry. Importing the same filename from the library creates a separate dataset.

Table inspection runs locally without a model. It supports UTF-8 CSV, TSV, JSON, and JSONL. Imports are limited to 10 MiB. See Data versions, provenance, and checks.

Recheck one result from Fisher’s paper

  1. In Paper, import the original Fisher (1936) PDF used for the case. For those exact file bytes, the toolbar offers Select Fisher Table III result.
  2. Review the original table, 100 input measurements, calculation, and comparison rule. Freeze the protocol and explicitly confirm a run. Compare the reported 19.1434 cm² with the computed value, difference, and independent numerical check.
  3. Export the evidence ZIP, extract it, and run the command below in the extracted directory. The independent check uses the Python standard library and requires no network or model.
python -I -S verify.py

The recorded REPRODUCED verdict covers one value in the table. The paper-level verdict remains NOT_ASSESSED. See the Fisher case inputs and acceptance record.

Link material to a research project

Choose New research project and enter a name and research goal. You can also attach a local directory. Open Materials & experiments → Link existing records, choose an enabled App, and link a saved paper, study, or experiment.

The project stores links to the original records. Open a link to see the record in its App. If the record changes, review it and update the linked revision when needed. See research project behavior and verification.

Prepare a remote computation

With an authorized SSH or Slurm environment, choose a connection in Compute, probe it, and prepare the bundled CPU midpoint quadrature method. Review the destination, frozen parameters, and requested resources before approving submission.

Return to the original attempt to observe status, read logs, and collect saved artifacts. Verification covers an actual loopback SSH server and a Slurm fixture. Real Slurm sites and other scientific methods need separate acceptance. See the Compute guide and verification record.
