Record methods and reviewable evidence

Save text, formulas, and evidence references in a Notebook revision. Try a small calculation, then attach a paper citation or experiment record beside a finding.

Create your first notebook revision

The steps below were verified in a fresh profile of the November 12, 2026 Electron preview on Apple Silicon macOS.

  1. Open Notebook in the workbench sidebar. It is already installed and enabled in this preview. If you see Environment not ready, select Prepare environment and wait for the New notebook button. The first launch may download Python and dependencies. If preparation stalls or fails, open Installation log before retrying.
  2. Choose New notebook, name it Spreadsheet and revision practice, and write down the input 2 and multiplier 6. The newly created notebook starts at Revision 1.
  3. Choose Insert → Spreadsheet. Type 2 in A1 and =A1*6 in B1. Select another cell to commit the formula. Once you leave B1, it should display the evaluated value 12.
  4. Choose Save revision. The toolbar should report Revision 2. Change A1 to 3, leave the cell, and save again. Check for Revision 3 and B1 = 18.

Open File → Revision history → Revision 2. The read-only view should show A1 = 2 and B1 = 12. The sidebar still shows the current saved revision. Choose Return to current notebook to get back to Revision 3. Use Restore as draft only when you want to edit from the old content.

To check persistence, close Pero, reopen Notebook, and select the saved entry. The release test reopened Revision 3 with A1 = 3 and B1 = 18.

If saving conflicts with another edit, choose Export draft to preserve your changes before reviewing the latest revision. Loading the latest revision discards the current draft.

Put the finding beside its source

  1. Write a specific finding and identify its metric, data scope, units, and uncertainty.
  2. Insert an Evidence block. Paste a saved Paper citation or passage link, or import a Paper report JSON, choose the citation, and attach its snapshot. Expect an excerpt with the report or location identity.
  3. For an experiment, export evidence JSON from Control Lab. Insert an Experiment reference in Notebook, load the JSON, choose the specific trial, and attach a snapshot. Open the original App to inspect that attempt’s inputs, result, and checks.
  4. Save the revision. Review the notebook revision, source version, and original evidence together. If the source App adds results, earlier Notebook revisions still show the snapshots they saved.

Notebook stores the version and evidence you selected. The source App holds the computation, source updates, and verification. Use the citation review workflow to check key claims.

Choose the right export format

  • For the complete document, choose File → Export current JSON. In the release test, Notebook.json contained the practice title and raw cell formula =A1*6. This export includes the document and stored evidence references. Open the desired saved revision before export to capture that snapshot. Exporting the current notebook can include unsaved edits.
  • Use File → Export workbook for worksheet names, values, and formulas. The released App produced Notebook.xlsx with A1 = 3 and the A1*6 formula in B1. The workbook is marked for recalculation on open. Use the JSON format when you need Notebook evidence, or Markdown for the text.
  • For Agent review, save a revision and choose File → Ask Agent. In the release test, the composer opened a draft referencing the saved Revision 3. Inspect the reference and text before you send, then review any reply against that revision and the source evidence.

To check the JSON export, open the … beside New notebook and choose Import notebook JSON. The practice export opened as a separate Revision 1 with A1 = 3 and B1 = 18. The original entry remained at Revision 3.

If floating Chat covers the bottom of the File menu, use Close chat (the minus button) or Dock chat in the Chat header. Reopen File to reach Export workbook.

A worksheet supports up to 200 rows and 50 columns, scalar formulas, and references across sheets in the same notebook. External workbook links, network functions, and dynamic array spilling are outside the supported subset. See the format documentation and the workbench verification record.

Build a manuscript from a saved revision

Use a current source build for the MyST publication workflow. Start with a MyST manuscript, a working Tectonic engine, and a prepared package cache. Save the revision containing the manuscript block and choose Compile saved revision to PDF from that block. Check the exact revision, log, and output in build history before previewing or downloading. The package walkthrough above exercised worksheet and JSON exports.

After editing data or generating code, regenerate stale figures and update the document before you save a new revision. Failed builds retain inputs and diagnostics. The last successful PDF remains available in history. PDF compilation confirms the manuscript renders. Scientific claims require their own review. Follow the Fisher manuscript example with commands and expected output.
