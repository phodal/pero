Objects in the workbench

Research project
Holds a research goal and links to App records, with an optional local directory.
App
Provides a domain interface, methods, and data. Paper holds papers and research reports. Data holds dataset versions.
Host and Agent session
The Host manages local Apps, credentials, Agent sessions, approvals, and cancellation. Review pending tool requests in the conversation.
Control plane and Worker
The optional control plane coordinates shared tasks. A separate Worker handles them in its configured execution environment. The services need their own deployment and authorization.

See the architecture guide and App development guide for ownership and integration details.

Data, permissions, and costs

  • Apps store domain data on the machine where they run. Model providers, literature services, MCP connectors, or shared task services can receive selected data when you use them.
  • Local plugins and App backends run trusted code. Review where an App came from, the session's permissions, and the submitted content before using sensitive material.
  • Model and remote compute providers handle billing. Consult provider records for charges. Research step and time limits constrain the workflow.

Verification and support

The quality gates record source checks, desktop runs, external services, and packaged release results by feature. When evaluating a scientific result, check its sources, run inputs, comparison rules, and independent review. The roadmap covers planned team sync and shared research memory.

When reporting a problem in GitHub Issues, include the version or source revision, platform, Electron or Native, reproduction steps, and any shareable error details. See the contributor guide to make a code change.
