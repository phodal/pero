# SciSpace 与 BioMed Agent 竞品详解

核验日期：2026-11-07。对象：SciSpace 通用研究平台、BioMed Agent 与企业版本。依据官方页面和 credits 指南；未登录执行、未上传数据、未评价模型科学正确性。平台展示的数量、可复现性和生产率均属于厂商主张。

## 核心判断

SciSpace 已从论文阅读/写作工具扩展为研究代理平台。BioMed Agent 把单细胞、多组学、变异解释、药物相关计算和实验协议推理列为场景，因此它与 Pero 的竞争不只在 Paper，也延伸到 Research 和生命科学分析体验。与此同时，工作流展示不是完整科学验证，也不能证明它具有与 Pero Host 相同的任意本地/HPC 环境控制。

## 产品定位与目标客户

- **通用 SciSpace：** 论文搜索、综述、PDF 解释、数据抽取、写作和研究产物的统一入口。
- **BioMed Agent：** 面向多组学、临床表型和实验协议推理的专门研究代理，页面标 New Release。
- **Enterprise：** 面向企业/机构研发团队，提供定制工作流、资料接入与管理/安全能力。
- **使用者：** 学术实验室、学生、计算经验有限的研究者、临床科研人员以及 biotech/pharma；企业产品也面向医疗器械、消费品、制造和 CRO。[主站](https://scispace.com/)、[BioMed](https://scispace.com/biomedical?agentmode=biomedical)、[Enterprise](https://scispace.com/enterprise)

“某机构研究者使用”不等于该机构统一采购。企业页与主站用户量口径不同，本报告不以这些数量比较市场份额。

## 功能范围

### 通用研究入口

主站公开提供 Agent、PDF Chat、Literature Review、AI Writer、引用生成和数据抽取，亦有 diagram/presentation 等产物入口，另有浏览器扩展和移动入口。它覆盖寻找资料、读懂文献、组织内容到交付研究材料的连续体验。[SciSpace 主站](https://scispace.com/)

写作工具、AI detector 或 humanizer 的存在不代表能保证学术合规、准确识别 AI 文本或替代研究原创性判断；本报告不将这些工具作为科学质量优势。

### BioMed 工作流

公开示例包括：单细胞数据聚类/细胞类型标注、snRNA 与 snATAC 的调控网络分析、候选基因/变异优先级、靶点和筛选设计、药物再利用及 ADMET 相关计算。页面宣称具备 100+ 软件包、150+ 专业工具和多种生物数据库，可将任务串联成可复现流程。[BioMed Agent](https://scispace.com/biomedical?agentmode=biomedical)

这些数字说明其产品范围，不说明各工具能否被正确选择、参数是否适合数据、结果是否达到研究验收标准。尤其“变异或罕见病推理”是研究场景展示，不应作为个体诊断结论使用。

### 企业能力

企业页面描述批量 PDF 抽取、筛选到报告、演示材料、研究空白与基金申请草稿、资料/应用接入及定制代理。页面称上传文件置于隔离加密环境，并有 SOC 2 Type 2、RBAC、SSO；具体保留期、模型供应商、训练政策和审计导出应以合同确认，不能从一句“enterprise-grade”推定所有条件。[企业产品说明](https://scispace.com/enterprise)

## 完整任务流程

以下为公开能力的研究流程整理，不是现场使用记录：

1. 输入研究问题，选择通用 Agent 或 BioMed 路线。
2. 检索公共资料或导入有权使用的 PDF/数据。
3. 形成问题拆解与分析路径，决定调用的数据库、软件包及模型。
4. 执行文献/数据分析，并产出证据、表格、图或生物学解释。
5. 研究者检查来源、样本元数据、参数、方法局限及输出一致性。
6. 继续修改或制作综述、报告/演示，必要时进入下一轮研究。

这条路径在产品层面连贯，但本次未证实每个 BioMed 场景都有同等深度的日志、参数锁定、环境导出和恢复语义。因此不将“complete reproducible workflow”直接译成已验证的端到端可复现保证。

## 形态、部署与可用性

| 项目 | 公开依据 | 仍需验证 |
|---|---|---|
| 通用平台 | Web 自助输入和注册 | 账户具体权益及地区限制 |
| BioMed | New Release，公开任务入口 | 各方案可用工具、运行大小、队列限制 |
| 企业 | 销售入口与定制方案 | SKU、接入交付、数据区域与 SLA |
| API | 主站有入口 | 具体端点、费用、权限与 BioMed 覆盖 |

没有取得完整自托管、离线运行或完整项目环境可导出的证据。平台可以有代码分析能力，但这与允许用户任意配置计算环境不同。

## 优势与局限

### 优势判断

- 文献、写作、图表和领域代理入口集中，有利于非计算研究者采用。
- BioMed 将常见任务表达为研究问题而非软件参数，减少初次上手门槛。
- 免费和不同价格档位，方便个人试用后再考虑团队使用。

### 局限和科学风险

- 工具链广度不证明方法选择正确；错误元数据、批次效应和数据泄漏仍可能被隐藏在漂亮图表后。
- “可复现”需要区分重复生成相似报告、重跑同一代码和独立得到同一科学结论。
- 临床表型/变异解释涉及严格领域标准，不能自动升级为临床决策能力。
- 专业任务的运行容量、代码可见性、输出导出、依赖锁定及失败恢复未实测。
- 企业数据治理承诺应验证访问控制能否传递到派生摘要和输出，而非只看原文件存储加密。

## 与 Pero 的对照

Pero 基线见 [统一基线](../README.md#pero-比较基线)。Control Lab 当前为受控仿真，Lab 为 PyLabRobot 软件仿真；以下不是对已完成物理实验能力的比较。

| Pero 方向 | 关系 | 应优先证明的价值 |
|---|---|---|
| Paper | 直接竞争 | 证据条件、冲突与计算结果的关联 |
| Research | 多步分析直接竞争 | 可检查方法、预算和失败处理 |
| Data | 输入/文献数据部分重合 | 样本与数据版本身份、可追溯修改 |
| Virtual Cell | 组学与模型分析邻接竞争 | 单独证明预测能力与适用域，不以工具数比较 |
| Host | 未确认等价环境控制 | 用户持有环境、产物及独立重跑能力 |
| Control Lab | 协议推理不等价受控仿真 | 约束求解、固定指标和独立结果检查 |

## 待实测清单

1. **单细胞流程：** 使用公开 h5ad 和已知注释，检测 doublet、批次及基因 ID 问题；盲评标注而非只看 UMAP 是否漂亮。
2. **多组学解释：** 比较不同预处理/参数后结论稳定性，检查相关网络是否被过度解释为因果。
3. **代码和环境：** 要求完整脚本、依赖版本、输入 hash 与随机种子，在干净环境重跑。
4. **证据完整性：** 对同名基因、不同物种和冲突研究进行测试，检查引用是否支持当前场景。
5. **额度与中断：** 记录相同研究目标消耗、并发与暂停恢复，不只比较月费。
6. **人工控制：** 取消、修改关键方法或上传新版本后，任务能否正确停止/重算并保留旧结果。

**产品建议：** Pero 应把“生成结果”升级成“交付能被别人复核的研究项目”。在价格和易用性上直接模仿 SciSpace 可能难以形成优势，方法审查、开放执行和完整数据/运行关系更值得先做。
