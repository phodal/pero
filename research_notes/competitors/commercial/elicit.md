# Elicit 竞品详解

核验日期：2026-11-07。对象：Elicit Search、Reports、Systematic Review、Research Agent 及方案。依据官方产品页和定价/帮助文档；未登录、未上传论文或执行系统综述。所有精度、节省时间和覆盖规模的公开数字均为厂商口径，不作为本报告实测结果。

## 核心判断

Elicit 不能再简单归类为“论文搜索加总结”。其成熟入口仍是文献筛选和结构化证据抽取，但 Research Agent 已公开描述生物数据库、数据建模、图表、报告与持续项目工作。它对 Pero Paper 构成强直接竞争，对 Research 的证据工作也有挤压；尚无本次可核实的任意本地/HPC 环境管理能力，不能因此扩大为整体工作台完全等价。

## 定位与客户

- **主要工作：** 研究问题的证据发现、筛选、字段抽取、综合与更新，而不只是从一篇 PDF 得到解释。
- **使用者：** 系统综述作者、学术研究者、药企/medtech 团队，以及其他需要证据支持决策的研发组织。
- **购买动因：** 把大量文献变为可检查的结构化材料，减少研究助理的重复工作，并让团队复用来源与结论。
- **产品形态：** Web SaaS，自助免费/付费账户，企业销售；部分方案列 API、团队协作和定制部署选项。[Elicit 产品总览](https://elicit.com/)

客户数量和名校 logo 不等于付费机构数量，也不证明每个研究领域具有同等表现。

## 功能体系

### 检索与来源

Search 使用自然语言/语义检索学术论文和临床试验，支持自有文档及接入机构订阅全文。应区分“可找到论文元数据/摘要”与“拥有全文使用权”；库规模不是全文许可范围，也不是检索召回率。[Search](https://elicit.com/solutions/search)

Research Agent 的来源进一步包括公开和专有文档、Open Targets/ChEMBL/DepMap 等结构化生物数据、监管信息、专利及开放网络内容。页面称可把论点定位到原文段落、表格或图，展示计划和证据过程，并持续保留项目上下文。[Research Agent](https://elicit.com/solutions/research-agent)

### 筛选、抽取和报告

Elicit 的系统综述功能着重筛选和数据抽取；交互式表格用于逐篇比较，自定义列便于提取研究设计、对象、干预、结局等。Reports 的搜索到综合过程可审阅，用户能修改材料范围和报告信息；“受系统综述方法启发的报告”并不等于已经满足正式系统综述所有方法要求。[产品总览](https://elicit.com/)、[Reports](https://elicit.com/solutions/reports)

Research Agent 也公开支持数据建模、计算、图表与生信分析产物，不能标成无计算能力。与此同时，未核实这些能力是否能替代用户任意 Python/R 项目、GPU/HPC 环境或完整环境导出。[Research Agent](https://elicit.com/solutions/research-agent)

### 持续研究

Library 保留并组织来源；Projects 保留研究上下文；Routines 用于持续跟踪新研究。具体任务频率、额度、通知和多人权限应按方案验收，而不能把展示的所有能力视作 Basic 免费权益。[产品总览](https://elicit.com/)、[方案](https://elicit.com/pricing)

## 完整工作流程

以下为根据产品功能整理的典型路径，不是本次试用记录：

1. 定义研究问题、对象、纳入/排除条件和要抽取的字段。
2. 检索论文/试验或导入已有资料，补充合法可访问全文。
3. 筛选候选文献并复核排除理由，修正检索范围。
4. 在证据表抽取字段，检查原文支持与缺失值。
5. 由 Research Agent/Reports 综合、计算或制图，形成引用报告。
6. 研究者核对研究设计差异、冲突证据与结论强度。
7. 导出交付，保存项目，并按需要通过 Routines 更新。

正式综述中，检索登记、数据库覆盖、去重、双人独立筛选、偏倚评价和统计综合不能因为报告自动生成而省略。是否由 Elicit 支持、需要人工完成或另接工具，应在项目设计时明确。

## 可用性、部署与治理

自助注册和 Basic 是现成商业入口；企业功能通过销售配置。价格页列出企业 SSO/SAML、2FA、定制来源/模板及 single-tenancy 等选项。这是可购买配置的公开描述，不等于每个免费账户都拥有相同安全条款，也不能推断可全量 on-prem 或离线部署。[企业方案](https://elicit.com/pricing)

与 Pero 的关键架构区别在于：Elicit 的核心交付是证据与综述工作流；Pero 面向更广的研究执行和项目状态。两者可竞争，也可能互补，集成 Elicit 检索/抽取不意味着需要重建其内容索引。

## 优势与局限

**优势判断：**

- 筛选、抽取表和句级/段落级出处把“检查答案”变成具体操作。
- 单次问题、长综述和持续项目之间衔接较自然，专业用户无需先建立代码环境。
- 自助定价清楚，团队可逐步升级，而不一定先采购大型企业科研平台。

**局限与风险：**

- 搜索覆盖与全文可访问性限制证据完整度；“无结果”不证明研究不存在。
- 表格、图片、单位与亚组信息易出现抽取歧义，自动化不能取消领域复核。
- 公开示例中的准确率或速度不能外推到所有学科与文档质量。
- 摘要正确可能仍漏掉方法限制和冲突证据；来源可点击不代表每个 claim 已被证实。
- 不是本次已证实的通用科研运行时；环境快照、任意脚本执行、失败恢复和独立重跑能力需另测。

## 与 Pero 的对照

Pero 比较基线见 [统一基线](../README.md#pero-比较基线)，对照指研究方向而非已实现或待补全清单。

| Pero 方向 | 关系 | 值得做的差异 |
|---|---|---|
| Paper | 最直接竞争 | 连接论文 claim、数据版本、计算与反证 |
| Research | 证据规划/分析部分重合 | 从证据结论进入明确可执行且可审查的研究任务 |
| Data | 文献表格及输入资料部分重合 | 将引用来源与实验/计算数据统一标识 |
| Host | 未找到等价任意计算环境控制证据 | 证明固定环境重跑和多主机移交 |
| Virtual Cell | 生信分析邻接，不等价细胞预测 | 对模型科学质量单独验收 |
| Control Lab | 无足够等价受控仿真证据 | 固定指标、约束、独立检查及失败恢复 |

## 待实测与验收建议

1. **召回与筛选：** 用已有金标准文献集和预设标准，测关键研究漏检率；包括反面结果、旧术语和别名。
2. **字段抽取：** 对复杂表格和亚组信息双人标注，统计数值/单位/样本定义错误及“未报告”是否被编造。
3. **引用蕴含：** 随机逐句检查原文是否真正支持结论，区分摘要、全文、图表与推测。
4. **研究更新：** 新论文/更正加入后，结论、证据表和历史版本是否同步且可回溯。
5. **导出连续性：** RIS/CSV/BIB/PDF/DOCX 等可用格式是否保留完整出处、字段定义与修改记录，按购买方案实测。
6. **成本：** 用完成一个可发表证据包的总工时、专家修正量与订阅用量比较，而不是按聊天次数。

**产品建议：** Pero 不宜优先复制 Elicit 的检索与证据表全套体验。更明确的切入是把已审阅证据转成数据与计算项目，做到从一条论文结论追到具体运行，且可以反向验证。
