# Covidence 与 Pero 的竞品研究

[返回总索引](../README.md)

核验日期：2026-11-07。依据官方工作流、定价及提取共识文档；未登录实测。

**结论：** Covidence 的核心竞争力是把综述规则、人员责任和决策留痕做成工作流。Pero 若想服务严肃证据研究，需要的不只是更快生成综述，还包括可检查的筛选、提取、冲突处理和再审机制。

## 1 产品定位与目标用户

Covidence 是专门用于系统性审阅研究的协作平台，主要服务系统综述、范围综述、临床指南等项目的研究者、学生、临床人员和机构。其工作单位是 review，以及 review 中的候选研究、筛选决定、提取字段、质量判断和审阅者角色。

**官方重心：** 从研究问题和纳入标准设定，到文献导入、去重、筛选、数据提取、质量评价和导出，形成统一流程。[平台工作流](https://www.covidence.org/)

**竞争判断：** 它是证据团队操作系统的专用参照，不是通用自主科学 Agent。与 Pero 的直接重叠主要在 Paper 和多人证据复核；但它对“何为完成研究”的定义比自动生成一份报告更严格。

## 2 功能与实际工作流

以下为官方流程还原，**本次没有实际建立 review 或执行筛选**。

1. 确定研究问题、协议、纳入排除标准和团队角色。
2. 从数据库或文献管理器导入记录，处理重复文献，保留原始检索来源。
3. 进行题名摘要独立双人筛选，通过盲法减少互相影响，对冲突作明确决策。
4. 获取全文，记录全文排除原因，使后续报告中的筛选数量有依据。
5. 用团队模板提取字段，核查建议所指向的来源文本，再确认进入最终数据集的值。
6. 同时进行偏倚风险或质量评价，完成提取共识，导出数据和流程报告。[筛选与提取工作流](https://www.covidence.org/)

**提取共识的具体语义：** Extraction 2 在两位审阅者提交后进入共识；冲突字段需要最终选择或编辑，两人都留空的字段不会自动被视为冲突。完成后再修改审阅数据可能重新进入需共识状态。模板重新发布会影响不同阶段的研究，团队需要决定是否重开已完成项。[Extraction 2 共识流程](https://support.covidence.org/help/consensus-9831e0af)

上述细节很重要：界面显示“无冲突”并不等于“字段完整”，模板改动也不只是一次无害的表格编辑。

## 3 优势及其产品意义

- **把质量控制变成日常操作。** 谁筛选、为何排除、谁解决冲突，不需要依靠聊天记录追忆。
- **多人并行而不丢责任。** 独立判断和共识状态明确，适合把学生、主审研究者和方法专家组织到同一项目中。
- **降低综述管理负担。** 标准化提取模板、来源定位与导出减少跨表格搬运，但实际节省时间仍待测试。
- **承认人类决策的重要性。** 当前有筛选排序和提取建议等辅助，不能称它为“纯手工产品”；同时，建议不自动替代研究者确认。[官方功能](https://www.covidence.org/)

## 4 局限与使用边界

**检索完整性仍是研究团队责任。** 导入、去重和筛选平台不能补救检索协议本身遗漏了关键数据库或灰色文献的问题。

**流程合规不保证研究结论正确。** 两位审阅者达成一致，可能是共同误读；两位都未填写的字段也不会自然触发冲突。最终仍需领域和方法学检查。

**不是通用计算执行平台。** 本次没有公开证据足以确认其可替代用户控制的代码环境、任意实验管线或大规模计算任务。统计合成与科学分析仍可能需要其他工具。

**自动化效果未独立验证。** 官方展示提取建议和来源位置，但本次未测数字、单位、亚组、时间点及表格跨页情形的准确性，不应把演示视为质量保证。

**模板变更会带来返工。** 应在正式提取前用少量研究试填模板，并记录版本和生效范围，否则已完成研究的字段语义可能发生变化。[模板变更行为](https://support.covidence.org/help/consensus-9831e0af)

## 5 部署、价格与许可

Covidence 是商业托管服务，官网明确无需安装软件。标准格式兼容、数据导出和协作者邀请不等于产品开源或可自由自部署。

2026-11-07 官方价格如下，单位明确为 USD：[官方价格](https://www.covidence.org/pricing/)

| 方案 | 标价 | 范围 |
| --- | --- | --- |
| Single | 339 USD/年 | 1 个 review，12 个月有效，不限受邀协作者 |
| Package | 907 USD/年 | 最多 3 个 review，12 个月有效，不限受邀协作者 |
| Institutions | 联系报价 | 院系或组织授权 |
| Trial | 免费试用入口 | 页面展示可用 500 条记录试用 |

官网列出 RIS、CSV、PubMed XML 及常见文献管理工具的工作流兼容。购买前应先查机构是否已有授权，并确认到期后编辑、导出、保留与续期规则；本次没有核验最终结账条款。

**成本判断：** 与按座席收费的产品不同，这里的关键单位是 review 和授权期限。比较成本时应计算一个项目的完整周期、参与人数及中途暂停时间，不能只看月均价格。

## 6 与 Pero 的比较和设计启示

Pero 以 master `371ea089` 为本次比较基线，涵盖 Paper、Data、Control Lab、Virtual Cell 和 Host 等研究工作空间能力。可确认事实和未验证范围统一见 [Pero 比较基线](../README.md#pero-比较基线)；本篇没有独立重验 Pero 代码或科学性能。

| 层面 | Covidence 的公开能力 | Pero 的机会或缺口 |
| --- | --- | --- |
| 证据筛选 | 独立审阅、冲突、排除原因 | 不把 Agent 的一次判断直接当纳入事实 |
| 字段提取 | 模板、来源建议、共识 | 保留值、来源位置、审阅人和模板版本 |
| 变更影响 | 修改后可能重新进入共识 | 将证据变化传播到实验与结论依赖 |
| 科学执行 | 专注综述，不是通用实验环境 | 连接可审计证据和可复算实验 |
| 部署控制 | 商业托管 | 若强调开源，仍需达到可用的团队质量控制 |

**建议最小设计：** 每项证据有“候选、已审阅、冲突、确认、失效”状态；每个排除和修订有理由；Agent 只能提交建议而不能抹去人类原判断。状态名称是对 Pero 的建议，不是声称 Covidence 使用完全相同的内部模型。

## 7 建议实测与待验证问题

准备一个小型但包含重复、全文不符、结果单位冲突和遗漏字段的公开文献集，由两人按同协议分别完成任务。

- 去重是否误合并同试验不同报告，能否恢复？
- 双人筛选是否真正隐藏另一人的判断，冲突及权限如何工作？
- 提取建议能否定位到 PDF 中正确片段，数字、单位与时间点是否一致？
- 共同空白是否被完整性检查识别，还是被错误理解为完成？
- 模板变更后哪些研究被重开，历史值是否保留？
- 导出能否支持第三人重建纳入数量、排除原因和最终字段？
- Pero 能否接续这些证据，执行统计分析并保留原有审阅责任？

优先测审计重建成功率、严重筛选错误、提取字段准确性和完成项目的人工小时。不要仅比较生成一篇综述的速度。
