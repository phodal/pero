# scite 与 Pero 的竞品研究

[返回总索引](../README.md)

核验日期：2026-11-07。本文使用 scite 官方功能、价格及 API 页面，没有登录实测或独立分类准确率验证。

**结论：** scite 最值得 Pero 借鉴的是引文语境和冲突证据的可见性。它不只是论文搜索工具，也不是能够凭支持或反对次数判断科学真假的自动裁判。

## 1 产品定位与用户

scite 面向研究者、作者、编辑、同行评审者和机构，围绕论文如何被后续研究引用提供检索、核查与问答。产品的关键对象不是只有“论文”，还包括论文中使用其他研究的具体引文陈述。

**官方能力：** Smart Citations 将引文语境分为 supporting、contrasting、mentioning；Assistant 基于研究生成回答；Search 可以检索来自全文的引用陈述；Collections 用于组织和监控论文。[功能总览](https://scite.ai/features)

**产品判断：** scite 争夺文献核查和可信证据入口，并可作为 Pero Paper 的外部证据服务。它与通用研究工作空间的重叠主要在研究证据层，而不是实验执行层。

## 2 功能与可操作工作流

下面是根据官方功能还原的研究流程，**不代表本次实际使用结果**。

1. 从一个主张、DOI、论文或文稿中的参考文献列表开始。
2. 查看被引用论文的相关引文陈述，分别检查支持、对比或反驳、一般提及的原始上下文。
3. 在引用陈述中追踪方法、人群、实验条件或测量方式，判断两项研究是否真的回答同一个问题。
4. 用 Assistant 综合已找到的文献，但将“论文报告了什么”与“由这些结果推断什么”分开。
5. 对准备引用的文献运行 Reference Check，关注撤稿、编辑通知和相反证据提示。
6. 保存相关集合，监控新引用，再将经确认的证据移交写作或实验设计流程。

官方 API 提供 Assistant、Search、Smart Citation tallies 和 Reference Check 等结构化访问。Reference Check 的输入是文献列表，返回撤稿、编辑通知与相反证据相关标记。[API 功能](https://scite.ai/api)

## 3 优势及其来源

- **揭示“如何被引用”。** 同样是大量引用，一篇论文可能主要被当背景材料，也可能有实际支持或相反结果。引文语境比单一引用总数更适合进一步核查。
- **能从正文使用场景发现论文。** 方法细节或条件性结果可能不出现在题名摘要里，引用陈述检索为发现这些材料提供另一条路径。
- **适合写作前质量检查。** 撤稿和编辑通知提醒可以减少直接引用已出现重大问题文献的风险，但仍需人工判断通知内容。
- **便于嵌入已有工具。** 官方公开 API、MCP、Zotero 插件和浏览器扩展入口，产品价值不完全依赖用户留在其网页中。[功能与集成入口](https://scite.ai/features)

以上是产品能力分析，并未量化其减少错误的实际幅度。

## 4 限制与容易误读之处

**分类不是最终证据评级。** supporting 不证明原论文正确，contrasting 也不自动意味着原论文被推翻。研究对象不同、统计功效不足、术语差异和条件变化都可能影响解释。应回到引文原文与两篇论文的方法，而不是比较三个数字大小。

**覆盖不等于全文普遍可读。** 官方功能页同时出现文章索引、全文来源和引文数量，部分营销段落口径并不一致。本次不使用“全部索引文章均有全文”之类推断，也不据此排覆盖率名次。[当前功能页](https://scite.ai/features)、[API 数据口径](https://scite.ai/api)

**负面证据未被发现不代表不存在。** 后续研究未引用原文、引文尚未被索引、相关全文不可获得，都可能造成遗漏；这属于引文网络方法的边界，应通过实测估计。

**论文层与主张层不能混为一谈。** 同一篇论文可能在不同段落被支持和质疑。Pero 若只保存 DOI 和汇总计数，会丢失最有价值的上下文。

**未验证完整科研闭环。** 本次未发现足以确认版本化实验数据、可控计算环境或领域模型执行的公开证据。scite 的引用证据不能代替实验复算。

## 6 与 Pero 的比较

Pero 以 master `371ea089` 为本次比较基线，涵盖 Paper、Data、Control Lab、Virtual Cell 和 Host 等研究工作空间能力。可确认事实和未验证范围统一见 [Pero 比较基线](../README.md#pero-比较基线)；本篇没有独立重验 Pero 代码或科学性能。

| 层面 | scite 的强项 | Pero 应检验的差异化 |
| --- | --- | --- |
| 引文与核查 | 引用原文、分类与通知 | 在研究结论中保留主张级证据和冲突 |
| 信息组织 | 论文集合与监控 | 将外部证据映射到假设和实验版本 |
| 执行与复核 | 不以用户实验执行为主要产品重心 | 能否从论据追到数据、代码和独立复算 |
| 扩展方式 | 商业 API/MCP | 可替换供应方，避免把供应商分数当真值 |

**建议的集成对象：** 保存 DOI、引文所在论文、原始片段、章节位置、分类标签、抓取时间及来源服务。模型的解释应另存，不覆盖源文本。对没有语境的计数，不要计算貌似精确的统一“可信度分数”。

## 7 建议实测与待验证问题

建立一个人工审阅的主张集，覆盖支持、相反、无关引用、已撤稿和方法不匹配等情况，然后比较 scite 原界面、其 API 输出和 Pero 展示是否保持相同语境。

1. 分类错误是否集中在特定领域、语言、否定句或复杂统计表述？
2. DOI 级汇总能否可靠追溯到每条原文，而非仅给出总数？
3. 撤稿及编辑通知的发现延迟多大，是否覆盖对应版本？
4. 被引研究的真正相反结果是否能被找出，还是只发现字面否定？
5. 供应商数据更新后，Pero 已引用的旧判断如何重审？
6. 付费全文权限、缓存、再分发及批量使用有什么边界？

指标应包括人工判断一致性、严重漏报、误报导致的复核时间和可追溯率，而不只统计回答带多少引用。
