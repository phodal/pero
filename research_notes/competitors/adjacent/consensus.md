# Consensus 与 Pero 的竞品研究

[返回总索引](../README.md)

核验日期：2026-11-07。范围为公开产品、帮助中心、订阅和 MCP 文档；未登录实测。

**结论：** Consensus 是成熟的文献检索与证据综合入口，Research Agent 已支持多步研究，而非单次搜索加摘要。它既会争夺 Pero Paper 的用户时间，也可作为 Pero 可替换的上游检索服务。

## 1 产品定位与用户

Consensus 面向研究者、学生、临床专业人员和需要查证研究结论的知识工作者。其主要任务是从问题出发发现、理解和综合既有科学文献，减少从宽泛搜索结果中寻找可用研究的成本。[工作原理](https://help.consensus.app/en/articles/9922673-how-consensus-works)

**核心对象判断：** 产品围绕问题、检索结果、研究特征和带引用回答组织工作，不以用户自有实验运行、长期算力环境或实验资产注册为主要入口。这是产品重心判断，不是断言其永远不会扩展这些能力。

## 2 主要功能与可操作工作流

**官方事实：** Research Agent 能组合 DOI 查询、引文追踪、作者探索、相似论文、研究比较和空白分析，连续追问可继承上下文。用户可用自然语言叠加研究设计、样本量、发表时间等限制。[Research Agent](https://help.consensus.app/en/articles/12641232-research-agent)

依据文档可还原如下工作流，以下步骤未由本次研究实际操作：

1. 写出研究问题，并明确对象、干预或方法、比较条件、终点以及时间范围。
2. 先检索，再检查筛选条件是否准确落到系统检索上，不只确认回复“看起来理解了要求”。
3. 通过引用链和相似论文扩大候选集，检查是否存在不同研究设计或相反结果。
4. 要求按预先定义字段形成比较表，对每个研究保留 DOI、样本、方法、结果和来源位置。
5. 追问异质性、未覆盖人群或未解决问题，回到原论文复核数值和纳入理由。
6. 需要进入下一步分析时，导出或移交经确认的证据，而非让摘要直接替代原始文献。

**检索机制：** 官方描述使用语义与关键词混合检索，并结合相关性和研究信号排序；全文可用时会利用题名摘要之外的内容。相关性、引用量或期刊声誉是检索信号，不应被研究团队当作研究质量的最终裁决。[检索及分析机制](https://help.consensus.app/en/articles/9922673-how-consensus-works)

## 3 优势及其对产品选择的影响

- **问题到证据的路径短。** 用户无需先建复杂资料库，就能提出问题并得到可继续追问的研究结果。
- **学术字段进入检索本身。** 样本和研究设计约束比普通网页问答更贴近科研筛选需求，但实际字段准确性仍待抽样核查。
- **跨论文比较比单篇摘要更有决策价值。** 价值在于识别研究间一致和不一致的条件，而不是生成更多文字。
- **具备组件化入口。** 官方托管 MCP 可供支持 MCP 的助手调用，使其可能成为研究平台的基础供应方。[Consensus MCP](https://docs.consensus.app/consensus-mcp)

以上为依据公开能力作出的产品分析，不是使用时长、召回率或准确率测评结果。

## 4 局限、覆盖与可靠性

1. **不能把检索结果等同于系统综述。** 是否覆盖全部必要数据库、是否保存完整检索式和筛选记录，需要按照具体综述协议检查。
2. **全文并非处处可得。** 官方使用“when full text is available”的条件表述，实测必须区分摘要依据与全文依据，特别是样本分层、排除标准和结果数值。
3. **库规模口径不一致。** 2026-09 帮助文档写超过 2.2 亿篇同行评审论文，当前 MCP 文档写超过 4 亿学术文章、其中 3.5 亿同行评审论文。可能存在更新时差或集合口径差异，本篇不据此给出覆盖排名。[帮助文档](https://help.consensus.app/en/articles/9922673-how-consensus-works)、[MCP 文档](https://docs.consensus.app/consensus-mcp)
4. **引文存在不等于结论成立。** 要检查研究设计、外推范围、效应量及置信区间，不能只问答案是否带 DOI。
5. **不是完整实验闭环的已验证替代。** 本次未找到足以确认数据版本、用户控制运行环境和自主实验复核链的公开证据；这不表示相关能力必然不存在。

## 6 与 Pero 的比较及可行策略

Pero 以 master `371ea089` 为本次比较基线，涵盖 Paper、Data、Control Lab、Virtual Cell 和 Host 等研究工作空间能力。可确认事实和未验证范围统一见 [Pero 比较基线](../README.md#pero-比较基线)；本篇没有独立重验 Pero 代码或科学性能。

| 比较点 | Consensus 的公开重心 | Pero 的潜在切入点 |
| --- | --- | --- |
| 发现与综合 | 专用文献搜索、Agent 多步比较 | 无需重复建设全部检索基础设施 |
| 证据对象 | 论文、引用回答、研究比较 | 证据直接绑定假设、数据处理和实验决策 |
| 执行 | 本篇未验证通用实验环境 | 用可复算案例证明跨阶段连续性 |
| 开放性 | 商业服务和托管 MCP | 提供可替换供应方及本地 provenance 保存 |
| 质量责任 | 研究者需复核文献和结论 | 将确认状态、分歧及失败理由显式保存 |

**建议：** 先把 Consensus 作为可替换检索插件评估，同时测试 Pero 原生入口是否能在同任务上减少手工搬运。若最终仍需用户复制 DOI、重新上传文件、重复构建证据表，整体空间的价值尚未兑现。

## 7 建议实测与待验证问题

使用一个有公开金标准论文集的研究问题，预先固定纳入规则，分别执行关键词、语义和 Agent 多步检索。不要用生成综述的语言流畅度作主要指标。

- 金标准论文召回率、首批结果精确率和新增有效研究数。
- 摘要与全文依据是否标识，数值抽取是否能定位到原文。
- 研究设计和样本量筛选是否有误判，是否遗漏负面结果。
- 重复运行是否保存相同检索范围、结果版本与时间戳。
- MCP 输出是否包含足够标识符、来源和权限信息，失败时能否重试而不重复计费。
- 从证据表转入 Pero 实验任务需要多少人工步骤，转换丢失哪些字段。
